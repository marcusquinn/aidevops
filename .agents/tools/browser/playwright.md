# Playwright MCP

<!-- AI-CONTEXT-START -->

## Quick Reference

- **Purpose**: Standalone cross-browser testing and automation; use the extension only for interactive access to user-owned tabs
- **Install**: `npm install playwright && npx playwright install` (lib + browsers) | framework-managed pinned `@playwright/mcp` (MCP server)
- **Setup**: `./setup.sh --interactive` → "Setup browser automation tools"
- **OpenCode activation**: Invoke `@playwright`; it connects the disabled MCP on demand through the registry-allowlisted `aidevops_mcp` tool
- **MCP config**: generated by the aidevops registry with a pinned package, disabled startup state, and managed workspace launcher
- **Browsers**: Brave is preferred for separate headed/headless work; bundled Chromium is the fallback, with Firefox/WebKit available when required
- **Existing browser**: Interactive-only exception — use Microsoft's [Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) only when the user is available and the task needs approved tabs from their Chrome, Edge, or Chromium session; Brave support is not documented upstream
- **Default**: Fresh isolated headless Brave when available, bundled Chromium otherwise; authentication alone does not require an existing tab or headed mode
- **Headed exception**: Set `AIDEVOPS_PLAYWRIGHT_HEADED=1` for a separate visible browser when the user must assist (passkey, MFA, visual guidance) or the task requires visible UI | **Proxy**: HTTP/SOCKS5
- **Extensions**: `launchPersistentContext` (requires `headless: false`; `--headless=new` on newer Chromium)
- **Ad blocking**: Brave Shields or uBlock Origin | **AI page understanding**: `page.locator('body').ariaSnapshot()` ~0.01s, 50-200 tokens
- **Performance**: Navigate 1.4s, form fill 0.9s, extraction 1.3s, reliability 0.64s avg
- **Parallel**: 5 contexts in 2.1s, 3 browsers in 1.9s, 10 pages in 1.8s
- **Chrome DevTools MCP**: `npx chrome-devtools-mcp@latest --browserUrl http://127.0.0.1:9222`
- **Subagents**: `playwright-emulation.md` (device/viewport), `playwright-cli.md` (CLI agent)

## OpenCode Activation

aidevops keeps Playwright disconnected and its tool schema hidden globally. Use `@playwright` for browser work; it launches a fresh isolated **headless Brave** browser when installed, falling back to bundled Chromium. Authentication alone is not a reason to attach the user's tab or open a headed browser: use approved scoped credentials or session state in the isolated context. Set `AIDEVOPS_PLAYWRIGHT_HEADED=1` only when the user must assist (passkey, MFA, visual guidance) or the task requires a visible browser; the extension remains an explicit selected-tab exception. The bounded agent connects Playwright before its first operation and disconnects after completion. The activation tool accepts only MCP names declared by the plugin registry.

For bounded in-session browser operations, delegate to `playwright` with the target, authorization basis, allowed actions, stop-before actions and requested evidence. OpenCode prefers Luna xhigh for this child when available (interactive and headless), independently of the parent's standard/thinking tier; an explicit model pin takes precedence. Unavailable Luna falls back to connected Sol medium or the connected parent's model/effort. Keep final approval, interpretation and verification with the parent. On failure, return the last URL/page state and actions already taken; the parent must check for side effects before continuing itself or starting another child. Do not retry submits, payments, posts or other state-changing actions automatically. This routing applies to the OpenCode Playwright child, not the separate Python `browser-use` package or Browser Use Cloud model selection.

OpenCode launches Playwright inside a unique aidevops-managed temporary workspace and supplies that workspace's output directory to the server. Server-generated files and relative filenames supplied to output-producing tools stay there, including when OpenCode itself started in a canonical checkout. Absolute and `..` traversal output paths are rejected. Consume any review artifacts before disconnecting, and always disconnect when browser work finishes so the bounded workspace can be removed.

### Screenshot and Artifact Handoff

- **Parent request**: Give the child the parent's linked-worktree context, a relative filename such as `editor-desktop.png`, and the managed MCP output directory as the allowed storage boundary. If that directory is not known yet, ask the child to obtain it from the connected server's output; do not invent it or pass an arbitrary absolute destination to the screenshot tool.
- **Child capture**: Pass only the relative filename to the MCP tool. A rejected absolute path is not permission to save into the child process cwd, the parent repository, or a canonical checkout. Use the managed output directory; if its location cannot be established, report that limitation rather than guessing or searching unrelated checkouts.
- **Evidence report**: Use the normalized absolute artifact link returned by OpenCode, or resolve a server-reported relative link against the actual MCP output directory (never the child or parent cwd). Verify that the file exists and report its absolute path, for example with `realpath` on that known file. A relative link alone is not a successful handoff; if the absolute path cannot be verified, say plainly that it is unknown.
- **Lifetime**: The managed directory is temporary and removed on disconnect. Before disconnecting, consume the screenshot for review or, when the parent explicitly requests retained evidence, copy the verified artifact to the parent's allowed temporary evidence directory outside any repository and verify/report that retained absolute path. Do not claim a temporary path will remain available after disconnect. Always disconnect once evidence handling is complete.

For another MCP client without the managed launcher, configure an absolute `--output-dir` outside any repository under the aidevops temporary workspace and launch the server there, never in a canonical checkout. Continue to supply relative tool filenames and verify the server's actual output path; do not assume that client's cwd or output-directory behaviour matches OpenCode.

## Interactive Access to the User's Browser

Use Microsoft's Playwright Extension only in an interactive session where the user is available and the task specifically needs selected tabs from their existing logged-in browser. Never select it for headless workers, CI, scheduled routines, or ordinary headed/headless automation; use a separate Playwright browser with Brave preferred instead. Install the extension from the [Chrome Web Store](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm), then explicitly request Playwright MCP's `--extension` mode.

The extension's `PLAYWRIGHT_MCP_EXTENSION_TOKEN` bypasses its connection-approval dialog and is specific to a browser profile. Treat it as a credential: never paste it into chat, MCP configuration, shell history, logs, or repository files. Store and inject it with aidevops:

```bash
aidevops secret set PLAYWRIGHT_MCP_EXTENSION_TOKEN
PLAYWRIGHT_MCP_EXTENSION=1 aidevops secret PLAYWRIGHT_MCP_EXTENSION_TOKEN -- opencode
```

The aidevops MCP registry adds `--extension` only when the explicit flag is set and no headless-runtime marker is present; injecting the token alone does not switch modes. The token remains outside `opencode.json` and command arguments. Invoke `@playwright`, select only the intended tabs, and disconnect when finished. To retain per-connection approval instead of storing a token, run `PLAYWRIGHT_MCP_EXTENSION=1 opencode` and approve the connection in the extension UI.

For another MCP client, add `--extension` to its Playwright MCP command and inject the token into the client process with `aidevops secret PLAYWRIGHT_MCP_EXTENSION_TOKEN -- <client-command>`. If the extension reports "No clients are currently connected," the MCP/CLI process was not started in extension mode or has not connected yet.

Security boundaries:

- Treat every approved tab as authenticated browser control; avoid identity, finance, production-admin, and other high-impact tabs unless the task explicitly requires them.
- Require an interactive user for extension mode; never carry its opt-in flag into workers, CI, or scheduled routines.
- Keep the normal approval dialog unless unattended reconnection is necessary. A stored token removes that connection prompt.
- Use tab selection/groups to limit reach, do not expose unrelated tab details, and never close user-owned tabs or browser windows.
- Prefer isolated Playwright contexts for reproducible tests, CI, parallel runs, and any task that does not need the user's current session.

### Optional Human-Flow Recording

The third-party [Playwright Recorder](https://chromewebstore.google.com/detail/playwright-recorder/bapaclfmcgookbglclacfgeemaehkkme) can turn a low-sensitivity human demonstration into a draft Playwright script. Use it only when recorded actions materially clarify expected behaviour, and pair the result with written acceptance criteria. It handles browsing activity and page content, so never record secrets, personal data, payment steps, or sensitive authenticated journeys. Review and redact generated code before sharing or running it; do not treat it as a default install or a substitute for a product specification.

## Custom Browser Engines

Use `executablePath` for Brave, Edge, or Chrome instead of bundled Chromium. Brave is the preferred standalone browser for both headed and headless work because it runs separately from the user's everyday activity and its Shields may improve reliability on pages that challenge bare automation contexts.

| Browser | macOS | Linux | Windows |
|---------|-------|-------|---------|
| **Brave** | `/Applications/Brave Browser.app/Contents/MacOS/Brave Browser` | `/usr/bin/brave-browser` | `C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe` |
| **Edge** | `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge` | `/usr/bin/microsoft-edge` | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` |
| **Chrome** | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` | `/usr/bin/google-chrome` | `C:\Program Files\Google\Chrome\Application\chrome.exe` |
| **Chromium** (bundled) | Auto-detected by Playwright | Auto-detected | Auto-detected |

```javascript
import { chromium } from 'playwright';
const executablePath = '/Applications/Brave Browser.app/Contents/MacOS/Brave Browser';

// Simple launch
const browser = await chromium.launch({ executablePath, headless: true });

// Persistent context with extensions (headless: false required)
const context = await chromium.launchPersistentContext('/tmp/brave-profile', {
  executablePath, headless: false,
  args: ['--load-extension=/path/to/ext', '--disable-extensions-except=/path/to/ext'],
});
```

Managed Playwright and Browser QA honour `AIDEVOPS_PLAYWRIGHT_EXECUTABLE=/path/to/browser`; set `AIDEVOPS_PLAYWRIGHT_BROWSER=chromium` when bundled Chromium is required exactly.

## Bounded Completion Checks

This implements the outcome contract in `browser-automation.md` "Completion Outcomes" and the failure handoff in "OpenCode Activation" above. One locator union waits for whichever terminal state appears first, so a visible error ends the check immediately. A non-terminal loading screen still runs to the deadline. Locators must match the target's real states; arbitrary `body.innerText` substrings are weak evidence.

```javascript
import { chromium } from 'playwright';

const TIMEOUT_MS = 60_000;
const redactUrl = (u) => { const x = new URL(u); x.search = ''; x.hash = ''; return x.href; };
const actions = [];
const result = { outcome: 'failed', evidence: null };
const browser = await chromium.launch();
try {
  const page = await browser.newPage();
  await page.goto(process.env.TARGET_URL); actions.push('open');
  // ...perform the single state-changing action once, then actions.push('submit')
  const states = [ // priority order; first visible match wins
    ['success', page.getByRole('heading', { name: 'Detected structured data' })],
    ['blocked', page.getByRole('alertdialog').filter({ hasText: /log in|sign in|access denied/i })],
    ['failed', page.getByRole('alert').or(page.getByRole('alertdialog'))],
  ];
  try {
    await states.map(([, l]) => l).reduce((a, b) => a.or(b)).first()
      .waitFor({ state: 'visible', timeout: TIMEOUT_MS });
    for (const [outcome, locator] of states) {
      if (await locator.first().isVisible()) { result.outcome = outcome; break; }
    }
  } catch (error) {
    if (error.name !== 'TimeoutError') throw error;
    result.outcome = 'timed-out';
  }
  const text = await page.locator('[role=alert],[role=alertdialog],h1,h2').allInnerTexts();
  result.evidence = { url: redactUrl(page.url()), actions, text: text.slice(0, 5).map((t) => t.slice(0, 200)) };
} finally {
  await browser.close();
}
console.log(JSON.stringify(result));
process.exitCode = result.outcome === 'success' ? 0 : 2;
```

When success also depends on navigation, check the URL before reporting success, for example a new result ID. Do not loop this check around a submission. On `blocked` or `failed`, return the evidence; the parent checks side effects before trying again.

## Testing Patterns

For device emulation (presets, viewport/HiDPI, geolocation, locale/timezone, permissions, color scheme, offline, responsive breakpoints), see `playwright-emulation.md`.

| Need | Pattern |
|------|---------|
| Cross-browser | Iterate `['chromium', 'firefox', 'webkit']` and call `playwright[browserName].launch()` |
| Mobile | `browser.newContext({ ...devices['iPhone 12'] })` |
| Performance | `page.evaluate(() => performance.getEntriesByType('navigation')[0])` for Core Web Vitals; use CDP `Network.emulateNetworkConditions` for throttling |
| Visual regression | `expect(page).toHaveScreenshot('name.png', { threshold: 0.2 })` across `[1920, 1366, 375]` |
| Security | Inject XSS payloads via `page.fill()`, assert no alert dialogs fire, and verify auth redirects for valid/invalid credentials |
| API interception | `page.route('/api/**', route => route.fulfill({ json: mockData }))` or `page.waitForResponse(r => r.url().includes('/api/posts'))` |
